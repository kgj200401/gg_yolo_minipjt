# 파인튜닝 진행

## 1. 목표와 현재 상태

**잘못된 상품을 장바구니에 담는 일을 줄이는 정밀도를 우선하면서, 놓치는 상품도 줄인다.**
실험의 목표는 ‘정밀도 90% 이상인 조건 중 Recall이 가장 높은 설정’이다.
90%는 목표 기준이며 실제 카메라에서도 보장되는 수치는 아니다.

- 현재 웹앱 모델: `runs/detect/ozm_augmented/weights/best.pt`
- 자동 담기: 같은 상품이 **신뢰도 70% 이상으로 1초 이상** 확인되면 1개 추가
- 계속 보이는 상품은 중복 등록하지 않고, 사라진 것이 감지된 후 다시 나타나면 재등록
- 신뢰도 55%·60% 평가까지 완료했지만 **앱 설정은 아직 70%**
- B·C 실험 모두 완료했다. 정밀도 우선 목표에서는 A를 유지한다. C 해석은 9절 끝을 참고한다.

## 2. 용어를 쉽게 이해하기

| 용어 | 의미 |
|---|---|
| 파인튜닝 | 이미 학습된 모델을 우리 식재료 데이터에 맞게 추가 학습하는 것 |
| 가중치 | 학습하면서 바뀌는 모델 내부 숫자. 결과는 `best.pt` 등에 저장 |
| 에포크 | 전체 학습 데이터를 한 번 학습하는 단위 |
| 배치 크기 | 한 번에 처리하는 이미지 수 |
| 학습률 | 가중치를 얼마나 크게 수정할지 조절하는 값 |
| 얼리 스토핑 | 검증 성능이 일정 기간 좋아지지 않으면 학습을 멈추는 기능 |
| 신뢰도 기준 | 모델이 낸 결과 중 어느 점수 이상을 사용할지 정하는 값. 변경에 재학습은 필요 없음 |
| 정밀도(Precision) | 탐지한 것 중 정답의 비율. 오탐이 적을수록 높음 |
| 재현율(Recall) | 실제 정답 중 찾아낸 비율. 놓친 물체가 적을수록 높음 |
| F1 | 정밀도와 Recall을 함께 평가하는 조화평균 |
| mAP50 | 박스 IoU 0.5 기준에서 여러 신뢰도 구간을 종합한 클래스 평균 AP |
| mAP50-95 | 박스 IoU 0.5~0.95의 여러 기준으로 더 엄격하게 평가한 평균 AP |
| IoU | 예측 박스와 정답 박스가 겹치는 정도 |

‘정밀도 90%’와 ‘신뢰도 기준 90%’는 다른 의미다.
예를 들어 신뢰도 기준을 60%로 설정해도 평가 정밀도는 90% 이상일 수 있다.

## 3. 데이터와 공통 학습 설정

Roboflow에서 YOLOv8 형식으로 내려받은 데이터셋을 사용했다.
중복 설정 파일과 경로를 정리하고, 다각형 라벨을 객체 탐지용 외접 사각형으로 변환했다.
다운로드한 원본 ZIP은 보존했다.

| 분할 | 이미지 수 | 역할 |
|---|---:|---|
| train | 원본 622장 | 모델 학습 |
| valid | 78장, 정답 박스 216개 | 학습 중 성능 확인, 설정 선택 |
| test | 78장, 정답 박스 219개 | 모델 비교 및 평가 |

증강은 train에만 적용했다. 증강본은 새로 촬영한 독립 사진이 아니므로
비율을 맞추기 위해 valid·test로 옮기지 않았다.
원본 분할 사이에 파일 해시가 완전히 같은 이미지는 없었다.
다만 비슷한 장면이나 연속 촬영 사진의 중복까지 없다고 확인한 것은 아니다.

| 설정 | 값 |
|---|---|
| 시작 가중치 | 기본 `yolov8n.pt` |
| 장비 | RTX 4060 Laptop GPU, 약 8GB VRAM |
| 최대 에포크 | 150 |
| 배치 | 16 |
| 이미지 크기 | 640 |
| 옵티마이저 | AdamW |
| 초기 학습률 | 0.001 |
| 학습률 조절 | 코사인 감소, warmup 3에포크 |
| 얼리 스토핑 | 검증 성능 25에포크 미개선 시 종료 |
| 시드 | 42 |

두 모델 모두 기본 가중치에서 새로 시작했다. 증강 모델은 이전 `best.pt`를 이어받지 않았다.
`best.pt`는 검증 mAP50-95에 기반한 최고 모델이며, 정밀도만으로 선택한 파일은 아니다.

## 4. 기본 학습과 증강 학습

| 항목 | 기본 학습 | 증강 학습 |
|---|---|---|
| 학습 이미지 | 원본 622장 | 원본 622장 + 시계 방향 90도 회전본 622장 |
| 수평 뒤집기 | 확률 50% | 확률 50% |
| 추가 무작위 회전 | 없음 | ±15도 |
| 수평·수직 shear | 없음 | 각각 ±10도 |
| 기본 색상·이동·확대축소·Mosaic | 유지 | 유지 |
| 최고 에포크 | 102 | 121 |
| 종료 에포크 | 127 | 146 |
| 결과 폴더 | `runs/detect/ozm_baseline` | `runs/detect/ozm_augmented` |

수평 뒤집기는 기본 학습에도 적용돼 있었다. 증강 실험에서는 여러 변형을 동시에
추가했으므로 어떤 증강 하나가 성능 변화의 원인인지는 아직 분리해서 확인하지 않았다.

### 동일한 test 분할 비교

Precision·Recall·F1은 신뢰도 **0.70**, 정답 매칭 IoU **0.50**의 전체 물체 합산(micro) 기준이다.
NMS IoU는 0.70이다. mAP는 별도로 낮은 신뢰도 0.001부터 예측을 수집해 계산했다.

| 지표 | 기본 모델 | 증강 모델 | 변화 |
|---|---:|---:|---:|
| **Precision** | 80.87% | **92.81%** | +11.93%p |
| Recall | 67.58% | 58.90% | -8.68%p |
| F1 | 73.63% | 72.07% | -1.56%p |
| mAP50 | 82.44% | 83.53% | +1.09%p |
| mAP50-95 | 63.54% | 63.98% | +0.45%p |
| 정답 탐지 TP | 148 | 129 | -19 |
| 오탐 FP | 35 | 10 | -25 |
| 미탐 FN | 71 | 90 | +19 |

**해석:** 오탐 25개를 줄였지만 정답도 19개 덜 찾았다. 모든 성능이 좋아진 것은 아니다.
마늘은 정답 탐지가 35개에서 18개로 줄어 Recall 하락의 큰 부분을 차지했다.
마늘 Precision은 70%→100%, Recall은 87.5%→45%로 변했다.
표본이 작은 클래스의 100%는 실환경 무오탐을 의미하지 않는다.

검증 최고 mAP50-95도 기본 모델 72.87%, 증강 모델 66.12%였다.
학습을 길게 하거나 증강을 늘리면 무조건 좋아진다고 판단할 근거는 없다.

## 5. 첫 튜닝 실험: 신뢰도 기준 비교 — 완료

### 방법

- 현재 증강 모델을 그대로 사용하고 **재학습하지 않았다**.
- valid 78장으로 0.50~0.90을 0.05 간격으로 비교했다.
- test는 이번 실험에 사용하지 않았다.
- 정밀도 90% 이상인 조건 중 Recall이 가장 높은 조건을 찾았다.
- 정답 매칭 IoU 0.50, NMS IoU 0.70, 입력 640을 유지했다.

| 신뢰도 기준 | Precision | Recall | F1 | TP | FP | FN |
|---|---:|---:|---:|---:|---:|---:|
| 50% | 86.90% | 67.59% | 76.04% | 146 | 22 | 70 |
| **55%** | **90.32%** | **64.81%** | **75.47%** | 140 | 15 | 76 |
| **60%** | **90.32%** | **64.81%** | **75.47%** | 140 | 15 | 76 |
| 65% | 91.72% | 61.57% | 73.68% | 133 | 12 | 83 |
| 현재 70% | 91.67% | 56.02% | 69.54% | 121 | 11 | 95 |
| 75% | 92.56% | 51.85% | 66.47% | 112 | 9 | 104 |
| 80% | 93.75% | 48.61% | 64.02% | 105 | 7 | 111 |
| 85% | 94.57% | 40.28% | 56.49% | 87 | 5 | 129 |
| 90% | 94.44% | 23.61% | 37.78% | 51 | 3 | 165 |

이번 검증의 mAP50은 83.65%, mAP50-95는 66.10%다.
mAP는 신뢰도 한 지점의 정밀도와 다른 지표이므로 각 행마다 다시 성능 향상 수치로 해석하지 않는다.

### 판단

55%와 60%가 이 검증 표본에서 같은 결과를 냈다. 평가 스크립트는 동률의 첫 값인 55%를
선택했지만, 실제 카메라 시험 후보로는 그중 높은 기준인 **60%**를 제안한다.
60%가 다른 데이터에서도 더 좋다고 입증된 것은 아니다.

70%→60% 변경 시 검증 결과:

- 정밀도 **1.35%p 감소**, Recall **8.80%p 증가**, F1 **5.93%p 증가**
- 정답 19개를 더 찾는 대신 오탐 4개 추가
- 목표 정밀도 90%는 근소하게 넘었으므로 새 영상에서도 확인 필요

**주의:** test 정밀도 92.81%와 valid 정밀도 91.67%는 서로 다른 데이터의 결과다.
조건 변경 효과는 같은 분할 내에서 비교해야 한다.

## 6. 제안했던 단계와 변경 사항

사용자와 논의 후 카메라 시험은 보류하고 B 실험부터 진행하기로 했다.
아래 50에포크 계획은 초기 제안이다. 기존 모델과 같은 학습 정책으로 비교하기 위해
실제 B 실험은 최대 150에포크·patience 25로 변경했다. C는 아직 실행하지 않는다.

### 먼저: 신뢰도 60%·1초로 실제 카메라 비교

새 학습보다 먼저, 현재 70% 설정과 후보 60% 설정을 같은 영상에서 비교한다.
가능하면 영상을 한 번 녹화해 두 조건에 똑같이 재생하고, 새 장면·조명·거리도 포함한다.
상품별 10회 이상 등장시키는 것을 초기 점검 목표로 삼되 최종 통계 검증으로 과대해석하지 않는다.
빈 화면과 손만 나오는 장면, 상품을 치웠다가 다시 넣는 장면도 포함한다.

| 측정 항목 | 의미 |
|---|---|
| 등록 정밀도 | 자동 등록 중 올바른 상품 등록 비율 |
| 등록 성공률 | 실제 상품 제시 중 올바르게 등록된 비율 |
| 중복 등록 | 상품을 계속 보여줬는데 추가로 담긴 횟수 |
| 등록 지연 | 상품 제시부터 등록까지 시간 |

정지 이미지 평가에는 1초 유지·재등장 조건이 포함되지 않았으므로 앱 성능과 구분한다.
60%에서 오등록이 허용 범위 안이고 누락이 줄면 재학습을 보류할 수 있다.

### 필요하면: 짧은 재학습 B → 결과 검토 → C

| 실험 | 변경 | 학습 한도 |
|---|---|---|
| B | 90도 회전본 제외, 회전 ±15도·shear ±10도 유지 | 최대 50에포크, patience 15 |
| C | B와 같은 데이터, 회전 ±10도·shear ±3도로 완화 | 최대 50에포크, patience 15 |

B 결과를 먼저 보고 C 여부를 결정한다. 배치 16, AdamW, lr0=0.001 등 나머지 조건을 맞춘다.
기존 증강 모델의 50에포크 기록은 데이터 수와 학습률 일정이 달라 참고용이다.
짧은 실험이 유망할 때만 후보 하나를 길게 학습한다.
이후 검증에서 임계값을 선택하고, 최종 확인은 추가 독립 데이터에서도 수행한다.
기존 test를 이미 여러 차례 비교했으므로 계속 그 점수에 맞춰 튜닝하지 않는다.

## 8. B 실험: 90도 회전본 제외

### 개선될 수 있다고 생각하는 이유 — 아직 검증되지 않은 가설

1. **실제 카메라와의 모습 차이를 줄일 가능성:** 기존 증강 데이터 절반은 90도 회전본이다.
   실제 사용에서 그런 방향이 드물다면, 제외 시 실제로 자주 보이는 모습에 학습을 집중할 수 있다.
   단, 실제 방향 분포는 아직 측정하지 않았고 식재료를 돌려 보여주는 환경에서는 도움이 될 수도 있다.
2. **변형이 겹치는 부담을 줄일 가능성:** 90도 회전본에도 ±15도 회전·±10도 shear와
   기본 Mosaic·확대축소 등이 적용된다. 불필요하게 어려운 변형을 줄이면 원래 장면의 탐지에
   도움이 될 수 있다. 다만 90도 회전 자체는 사각형 라벨을 정확히 변환할 수 있는 증강이다.
3. **Recall 저하 원인을 분리해서 확인:** 증강 후 test 오탐은 35→10개로 감소했지만
   정답 탐지도 148→129개로 감소했다. 여러 증강을 동시에 추가했으므로 회전본의 영향은 아직 모른다.
   회전본만 제외하고 다른 설정을 유지해 정밀도·Recall 변화가 있는지 확인한다.

이 가설이 맞으면 정밀도를 크게 잃지 않으면서 Recall이 개선될 수 있다.
반대로 다양한 방향을 덜 학습해 성능이 떨어질 수도 있다. 결과를 보고 판단한다.

### 실제 실행 조건

| 항목 | A: 기존 증강 모델 | B: 이번 실험 |
|---|---|---|
| 시작 모델 | 기본 yolov8n.pt | 동일, 이전 best.pt 이어 학습하지 않음 |
| 학습 데이터 | 원본 622 + 90도 회전본 622 | 원본 622만 |
| 무작위 회전 | ±15도 | 동일 |
| 수평·수직 shear | 각각 ±10도 | 동일 |
| 수평 뒤집기 | 확률 50% | 동일 |
| 기본 Mosaic·색상·크기·이동 증강 | 유지 | 동일 |
| 최대 에포크 / patience | 150 / 25 | 동일 |
| 배치 / 이미지 크기 | 16 / 640 | 동일 |
| 최적화 / 초기 학습률 | AdamW / 0.001 | 동일 |
| 코사인 감소 / 시드 | 적용 / 42 | 동일 |

### 임계값으로 제외되는 사례

이 진단 실행에서는 TP 119, FP 12, FN 97이었다.
FN 97개 중 46개에 같은 클래스·IoU 0.5 이상인 예측 박스가 존재했지만 신뢰도가 70% 미만이었다.
이는 낮은 신뢰도가 상당수 미탐에 관여함을 보여준다. 다만 한 예측이 여러 정답과 겹칠 수 있어
임계값을 내리면 정확히 46개가 복구된다는 뜻은 아니다.

**수치 구분:** 이 진단은 `predict()` 경로의 원본 이미지로 실행했다.
이전 공식 비교는 `val()` 경로이므로 전처리·정밀도 등 실행 차이로 경계 판정이 달라질 수 있다.
진단 TP/FP/FN을 기존 검증 성능 표에 덮어쓰거나 모델 성능 변화로 해석하지 않는다.

### 가장 먼저 할 일

**학습 횟수보다 ‘정답에서 상품 1개가 무엇인지’를 먼저 확정한다.**
현재 앱은 같은 클래스를 묶고 1개씩 등록하므로, 개별 식재료 조각을 모두 찾는 평가와
판매 단위 등록 목적 사이에 차이가 있다. 특히 마늘 봉지·햄 묶음·고기 팩이 중요하다.

1. 상품별로 낱개/봉지/팩/묶음의 박스 기준과 가림·경계 물체의 라벨 규칙을 작성한다.
2. 위 우선순위 사례의 정답을 사람이 확인한다. 특히 작은 마늘 박스와 햄 묶음부터 확인한다.
3. 확정한 기준으로 train에도 같은 문제가 있는지 점검하고 수정 목록·변경 이력을 남긴다.
4. valid 정답을 수정했다면 모든 비교 모델을 같은 수정본으로 재평가한다.
   정답을 바꾼 전후의 점수 차이는 모델 자체 개선이라고 보고하지 않는다.
5. 그 후 실제 카메라에서 누락이 많은 상황을 추가 수집하고 재학습 여부를 정한다.

사진에 보인다고 임의로 라벨을 추가하거나 기존 정답을 자동 변경하지 않았다.
이번 점검만으로 데이터 전체 오류 비율이나 새로운 성능을 주장하지 않는다.

## 13. 데이터 정리 2차 — 누락된 판매 포장과 사과 라벨 보완

### 추가 정리가 필요했던 부분

여기서 정리는 사진 수를 늘리거나 학습 설정을 바꾸는 작업이 아니다.
**사진에 실제로 보이는 상품과 정답 박스를 맞추는 작업**이다.

1. **누락:** 상품이 있는데 정답 박스가 없으면, 학습에서 그 부분이 배경으로 취급될 수 있다.
2. **범위·단위:** 계란 한 포장의 일부만 표시하거나 대파 한 단을 잎·줄기로 나누면 상품 하나의 기준이 흐려진다.
3. **중복:** 같은 상품에 동일한 박스가 겹쳐 있으면 중복 정답을 정리한다. 완전 중복은 1차에서 처리했다.

이번에는 1차에서 남겼던 계란·사과·대파 후보 5장을 검토했다.
정답이 없는 물체를 모델 예측으로 자동 채우지 않고, 원본을 보고 경계를 직접 지정했다.
계란 사진의 중간·아래 선반은 확대해서 포장 경계를 확인했다.

### 실제 수정한 두 사진

| train 사진 | 이전 | 수정 후 | 수정 이유 |
|---|---:|---:|---|
| `31f979235712cba7802420ec7a19b6f2...` 계란 진열대 | 박스 20개 | 박스 43개 | 누락된 판매 포장 추가, 한 포장의 일부만 표시한 범위 수정. 포장 안 계란은 따로 세지 않음 |
| `apple_006...` 사과 | 박스 20개 | 박스 32개 | 기존 20개는 유지하고 화면 경계에서 일부 잘렸지만 식별 가능한 사과 12개 추가 |

정답 박스는 보이는 범위에 맞췄고 가려진 크기를 추측해 확장하지 않았다.
수정 전후 그림:

- [계란 포장 20 → 43개](../runs/sale_unit_review_v2/corrected_01.png)
- [사과 20 → 32개](../runs/sale_unit_review_v2/corrected_02.png)

박스 수가 늘어난 것은 **라벨 누락을 보완한 결과**다. 이미지 수나 새 모델의 탐지 수가 늘어난 것은 아니다.

### 수정하지 않고 보류한 세 사진

| 사진 | 보류 이유 |
|---|---|
| `large green onion_001...` | 낮은 해상도에서 대파 묶음이 겹쳐 잎과 뿌리를 같은 단으로 연결하기 어려움 |
| `large green onion_017...` | 여러 묶음이 빽빽하게 겹침. 전체를 한 단으로 합치면 판매 단위 기준에 어긋남 |
| `apple_080...` | 통사과와 자른 사과가 섞여 있고 가림이 많아, 자른 부분을 별도 판매 단위로 볼지 불명확 |

보류 사진은 삭제하거나 빈 정답으로 바꾸지 않고 기존 라벨을 유지했다.
사과 `apple_006`에서도 너무 작은 배경 조각은 정체를 추측해 추가하지 않았다.
이러한 애매한 사례는 원본 고해상도·판매 맥락이 있는 사진이나 실제 카메라 촬영본으로 보완하는 편이 낫다.

### 저장 위치와 검증

- 누적 수정본: `dataset_corrected_v2/data.yaml`
- 수정본 + 새 90도 회전본: `dataset_corrected_augmented_v2/data.yaml`
- 재현 가능한 이번 수동 좌표·이유·보류 목록: [label_corrections_v2.json](label_corrections_v2.json)
- 누적 변경 전후 및 원본 해시: `dataset_corrected_v2/changes.json`

누적해서 train 라벨 5개 파일, valid 라벨 2개 파일이 원본과 다르다.
이번 추가 변경은 train 2개 파일뿐이다. train 정답은 1차 1,680개에서 **1,715개**로 35개 늘었다.
이미지는 기존과 같은 train 622장·valid 78장·test 78장이고, 증강 train은 622 + 622 = 1,244장이다.

확인한 사항:

- 원본 이미지·라벨 SHA256 일치: 원본 보존.
- v2의 valid·test 이미지와 라벨이 v1과 바이트 단위로 일치.
- train 완전 중복 행 없음, 라벨 좌표 범위 검사 통과.
- 수정 원본과 회전본 622쌍의 좌표 변환 검사 통과.
- 수정 전후 시각화에서 박스 확인.

```powershell

```

**현재 상태:** 2차 라벨 정리와 증강본 재생성 완료. 재학습은 아직 실행하지 않았다.

## 19. G 실험 — A 기준 물리적 배치 16 → 8

사용자 요청으로 `batch`만 16에서 8로 변경한다. lr0는 A와 같은 **0.001**, weight_decay는 **0.0005**다.
최대 150에포크, patience 25, AdamW, cosine, seed 42, imgsz 640, A의 데이터·증강은 유지한다.
`dataset_augmented/data.yaml`과 동일한 `yolov8n.pt`에서 새로 학습한다.

### 설치된 코드에서 확인한 실제 영향

Ultralytics `engine/trainer.py`는 `accumulate=max(round(nbs/batch),1)`을 사용한다.
현재 nbs=64이므로 워밍업 이후 A는 16×4, G는 8×8로 목표 누적 이미지 수가 약 64장으로 같다.
마지막 작은 배치와 워밍업에서는 정확히 64장이라고 할 수 없다. 워밍업 중 누적 횟수는 1부터 점진적으로 변한다.
따라서 물리적 배치를 줄여도 업데이트당 데이터가 단순히 절반이 되거나 업데이트가 두 배가 되는 실험은 아니다.

가중치 감쇠의 내부 배율은 `batch×accumulate/nbs`로 양쪽 모두 1이어서 optimizer에 전달되는 값은 동일하다.
`nn/modules/conv.py`에서 BatchNorm2d를 사용하는 것도 확인했다.
물리적 배치에 따라 BatchNorm이 사용하는 통계와 누적 과정·워밍업의 동작은 달라질 수 있다.
이 변화가 일반화에 유리한지 확인하는 탐색 실험이며, 배치 16이 문제라는 증거가 있는 것은 아니다.
작은 배치로 GPU 메모리 사용은 줄 수 있지만 한 에포크의 반복 수는 78 → 156으로 늘어 시간은 더 걸릴 수 있다.

학습 중 검증 배치도 기본 구현의 train batch×2 규칙 때문에 32 → 16으로 바뀐다.
이는 배치 변경에 따라 발생하는 부수 효과이며, 최종 비교 평가는 A와 G 모두 batch 16으로 통일한다.
최종 평가 정답은 동일한 수정 valid 78장, 신뢰도 65%가 주 기준이고 60%는 보조 기준이다.

### 어디를 어떻게 바꿨나

- `experiments/run_batch_experiment.py`: 학습 명령의 `--batch`를 `8`, `--lr0`를 `0.001`, 실험명을 `ozm_batch8`로 지정.
- `experiments/train_model.py`: 기존 `--batch` 옵션을 받아 `model.train(batch=args.batch)`로 전달하는 공통 코드 그대로 사용.
- `nbs`와 설치된 라이브러리 코드는 수정하지 않는다. 기존 실험 파일도 보존한다.
- 완료 후 실제 args 차이가 batch·실험명·저장 위치뿐인지 검사하고 A와 비교해 이 절에 자동 기록한다.

이번 전체 실험 실행 명령(실행 중에는 중복 실행하지 않음):

```powershell

```

- A 오탐은 10→8개, H는 21→16개. H의 기존 오탐 일부는 정답 누락의 영향이었다.
- 동일 수정본에서 A는 정밀도가 높고, H는 더 많이 찾으며 Recall·mAP가 높다. H는 TP 14개 증가와 FP 8개 증가를 함께 보인다.
- 누락 정답을 추가하면 못 찾은 물체도 늘어난다. Recall 하락은 이번에 모델이 나빠졌다는 뜻이 아니다. 정답이 달라진 전후 결과를 학습 개선률로 계산하지 않는다.
- 정밀도를 가장 우선하면 서비스는 **A·65%·1초 유지**. 정밀도 90%를 최소 조건으로만 두고 Recall을 높이면 이번 5% 간격 비교에서는 H·55%(P 90.91%, R 64.52%)가 후보가 된다. 자동으로 교체하지 않았다.
- 다음 우선순위는 고기·햄·양파의 판매 단위와 라벨 기준 확정이다. 보류된 기준을 train/평가 데이터에 일관되게 적용한 다음 재학습 효과를 비교한다.

코드: `experiments/prepare_validation_revision.py`의 `EDITS`에 이미지별 픽셀 좌표가 있다. 원본을 수정하지 않고 별도 폴더를 생성하며, 출력 폴더가 이미 있으면 중단한다. 검증: 원본 SHA-256 불변, 이미지 78장 일치, 라벨 좌표·클래스 범위 확인, A/H 각각 mAP 평가 및 신뢰도 9개 평가 정상 종료.

## 23. I 실험 — A 기준 cls 0.5 → 0.75

### 무엇을 왜 바꾸나

`cls`는 분류 손실의 비중이다. 0.5에서 0.75로 50% 높여, 학습 과정에서 상품 종류를 잘못 분류한 오류에 더 큰 비중을 준다. 증강 추가나 신뢰도 변경이 아니다. '정밀도가 50% 오른다'는 뜻도 아니다.

고기→새우, 계란 포장→햄 같은 클래스 혼동이 관찰되어 실험 후보로 선택했다. 0.75는 최적값으로 확인된 값이 아니라 첫 비교값이다. 위치 학습과의 균형이 달라지므로 Recall·mAP가 나빠질 수도 있고, 누락 라벨이나 판매 단위 문제를 직접 해결하지 못한다. 참고: [Ultralytics 학습 설정](https://docs.ultralytics.com/modes/train/).

| 설정 | A | I |
|---|---|---|
| cls | 0.5 | **0.75** |
| 시작 가중치 | yolov8n.pt | 동일, 새 학습(resume 아님) |
| 학습 데이터 | dataset_augmented/data.yaml | 동일 |
| 최대 에포크 / patience | 150 / 25 | 동일 |
| batch / imgsz | 16 / 640 | 동일 |
| optimizer / lr0 | AdamW / 0.001 | 동일 |
| weight_decay / cosine / seed | 0.0005 / 사용 / 42 | 동일 |
| degrees / shear / fliplr | 15 / 10 / 0.5 | 동일 |
| 나머지 증강 | A 설정 | 동일 |

학습 중 검증과 best.pt 선택도 A와 같은 기존 학습 YAML을 따른다. 최종 비교만 A와 I 모두 `dataset_corrected_v3_review/data.yaml`의 valid 78장을 사용한다. 검증 수정본은 미확정 단위가 남아 있는 검토용 데이터라는 한계를 유지한다. 기존 v2 결과와 섞어서 비교하지 않는다.

### 어디를 어떻게 수정했나

- `experiments/train_model.py`: `--cls` 옵션을 추가하고 `model.train(cls=args.cls)`로 전달한다. 기본값은 기존과 같은 0.5다.
- `experiments/run_cls_experiment.py`: `CLS_WEIGHT = 0.75`로 지정한다. A 재평가 → I 학습 → I 재평가 → 이 문서 결과 갱신 순서로 실행한다.
- 학습 종료 후 저장된 `args.yaml`을 A와 비교해 `cls`, 출력 이름·경로 외 설정이 달라지면 실패로 처리한다.
- 다음에 다른 값을 실험하려면 `CLS_WEIGHT`와 `RUN_NAME`, `OUT`, `REF` 출력 경로를 새 이름으로 바꾼다. 기존 결과가 있으면 덮어쓰지 않는다. 문서 결과 구역은 I 전용이므로 새 실험은 별도 구역·마커를 만들어 기록한다.
