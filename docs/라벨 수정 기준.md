# 라벨 수정 기준 — 판매 단위 확정

## 목적과 현재 상태

파라미터 실험 다음 단계로 train 622장의 정답과 A 모델 예측을 비교했다.
상위 오류 후보 12장을 직접 확인한 뒤, 판매 단위 후보 30장의 라벨을 추가 확인했다.
사용자가 판매 단위 기준을 승인했다. 수정본은 `dataset_corrected_v1`에 별도로 생성했다.
원본 라벨, 데이터 분할, 서비스 모델은 변경하지 않았다. 재학습도 시작하지 않았다.

## 확정한 상품 단위

사용자가 승인한 기준은 **판매 단위**다. 봉지·팩·묶음으로 판매하는 것은 전체에 박스 하나를,
포장 없는 낱개 상품은 각각 박스를 붙인다. 계란 한 판과 계란 한 알은 상황에 따라 단위가 달라진다.
사진만으로 판매 단위를 알 수 없는 햄 2팩·고기 접시 등은 임의로 합치지 않고 확인 대상으로 둔다.
봉지 내부의 낱개에는 별도 박스를 붙이지 않는다. 두 묶음이 보이면 각각 하나씩 표시한다.
포장의 빈 망 꼬리처럼 내용물이 없는 부속 부분은 상품 본체와 구분하고, 본체와 상품 표시를 중심으로 박스를 잡는다.

현재 앱은 같은 클래스를 묶어 장바구니에 1개씩 넣으므로, 여러 물건의 개수를 동시에 세는 기능과는 다르다.

## 공통 규칙

- 동일한 상품 단위에는 박스를 하나만 붙인다. 같은 물건의 잎·줄기를 별개 상품처럼 나누지 않는다.
- 확실히 식별되는 대상은 빠짐없이 표시한다. 모델이 찾았다는 이유만으로 정답을 추가하지 않는다.
- 박스는 보이는 상품 범위를 감싸되 화면 밖의 가려진 크기를 추측해 확장하지 않는다.
- 잘린 물체도 클래스를 확실히 식별할 수 있으면 보이는 범위에 표시한다. 애매한 사례는 검토 기록을 남긴다.
- 동일한 좌표·클래스의 완전 중복 행은 하나만 유지한다.
- 단위 기준을 바꾸는 경우 일부 오류 사진만 고치지 않고 해당 기준이 적용되는 전체 이미지를 검토한다.

## 구조 검사 결과

train·valid 라벨의 완전 중복, 이미지 경계 초과, 매우 작은 박스를 검사했다.

| 구분 | 파일 | 결과 |
|---|---|---|
| train | `carrot18_jpg.rf.QdBONoYFp8F3R2VdGyqH.txt` | 13번째 행이 앞선 행과 완전히 중복 |
| train | `shrimp_002_jpg.rf.2GXw5dFKEPKar1qHi5Lx.txt` | 5번째 행이 앞선 행과 완전히 중복 |

경계 초과는 매우 작은 반올림 오차 수준이며 주된 성능 문제라는 근거는 없다.
중복 2행도 기존 학습 로더가 제거한 것으로 기록되어 있어, 이것만 정리해 성능이 오를 것으로 기대하지 않는다.
기계적 검사 기록은 `runs/label_structure_audit.json`에 있다. test는 이번 구조 검사 대상에 포함하지 않았다.

## 적용 순서

1. 판매 단위 또는 식재료 낱개 기준을 확정한다.
2. 원본을 유지한 별도 데이터셋에 수정하고 이미지별 변경 전후와 이유를 기록한다.
3. 수정한 원본 train으로 증강본을 다시 만든다. 기존 90도 증강본의 오래된 라벨을 섞지 않는다.
4. 기존 train/valid/test 분할을 유지한다. 증강 이미지는 train에만 둔다.
5. valid 정답이 바뀌면 기존 A 모델부터 동일한 수정본으로 재평가해 새 비교 기준을 만든다.
6. 이후 A와 같은 학습 설정으로 한 번 학습해 데이터 수정 효과를 비교한다. 정밀도, Recall, mAP를 같은 조건에서 기록한다.

새로운 웹 카메라 사진은 별도 실사용 평가에 활용한다. 학습에 사용한 사진의 점수를 실사용 성능으로 보고하지 않는다.

## 1차 적용 결과

추가 확인한 30장 중 28장은 기존 박스를 유지했고, 대파 두 묶음과 마늘 두 봉지 2장의 박스를 수정했다.
햄 `ham_020`은 포장에 `120g × 2 PACK`으로 표시된 연결 상품이므로 기존 전체 박스 하나를 유지했다.
모델이 두 개로 나눴다는 이유로 정답도 두 개로 바꾸지 않았다.
별도로 train 중복 라벨 2행을 제거하고 valid의 미세한 좌표 초과 1행을 보정했다.

총 5개 라벨 파일 변경: train 3개, valid 2개. test의 이미지·라벨은 그대로다.
변경 전후 박스·이유·원본 SHA256은 `dataset_corrected_v1/changes.json`에 저장했다.
비교 그림은 `runs/sale_unit_review/corrected_01.png` ~ `corrected_05.png`다.

이것은 **확인한 오류의 1차 수정본**이다. 778장 전체를 판매 단위 기준으로 재라벨링 완료한 데이터셋은 아니다.
밀집 계란·사과의 누락 의심과 서로 겹친 대파 묶음은 추가 검토 목록에 남겼다.
특히 `large green onion_017`은 서로 겹친 묶음 경계를 확실히 구분하기 어려워 자동 병합하지 않았다.

## 2차 적용 결과

`dataset_corrected_v2`에 1차 수정을 유지하면서 train 사진 2장을 추가 수정했다.
계란 진열대는 누락된 판매 포장과 범위를 정리해 20 → 43개 박스로,
사과 `apple_006`은 식별 가능한 화면 경계 사과를 추가해 20 → 32개 박스로 보완했다.
대파 `001`·`017`과 통사과/자른 사과가 섞인 `apple_080`은 단위·경계가 불확실해 기존 라벨을 유지했다.
이번 좌표와 보류 이유는 [label_corrections_v2.json](label_corrections_v2.json)에 기록했다.
v2의 valid·test는 v1과 같고 재학습은 아직 진행하지 않았다.
