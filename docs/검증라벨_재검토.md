# A/H 비교를 위한 검증 라벨 재검토

## 목적과 범위

H의 오탐 중 일부는 실제 상품에 정답 박스가 없는 경우였다. 누락의 영향을 확인하기 위해 **재학습 없이 A와 H를 같은 수정 정답으로 다시 평가**한다.

이번 산출물은 `dataset_corrected_v3_review`라는 **검토용 검증 수정본**이다. 기존 v2를 대체하는 최종 정답으로 확정하지 않는다. 검증 78장의 축소 모음을 확인하고, 의심 사진을 확대 검토해 7장을 수정했다. 나머지 71장이 모두 정확하다는 의미는 아니다.

원본 이미지·기존 라벨과 train/test는 보존했다. 학습 가중치와 웹의 A·신뢰도 65%·1초 설정도 유지했다. 새 YAML의 train/test 경로는 기존 v2를 가리키며, 이번 실행은 `split=val`만 사용한다.

## 적용한 기준

- 같은 포장 안의 식빵은 내용물 전체를 하나로 표시한다. 비어 있는 비닐 꼬리는 제외한다.
- 독립적으로 포장된 식빵 두 봉지는 각각 표시한다.
- 사과는 식별 가능한 통사과·절단 사과를 표시한다. 화면 끝에 잘린 경우 보이는 범위를 사용한다. 절단면의 위·아래 볼록한 부분은 두 개로 나누지 않는다.
- 기존 사과 정답은 유지하면서 사과 검증 사진 6장을 모두 확인했다. 누락이 있는 4장에 추가했고, 단일 사과 2장은 유지했다.
- 고기는 경계가 명확한 누락 조각만 추가한다. 겹친 고기 더미의 개수를 예측 박스에 맞춰 추정하지 않는다.

절단 사과를 탐지 대상으로 포함하는 것은 **평가용 객체 기준**이다. 사과 조각 하나를 장바구니 한 상품으로 결제해도 된다는 의미는 아니다. 판매 단위 정책 및 작은 부분 객체의 포함 기준은 팀의 추가 검토가 필요하다.

따라서 **전체 검증 라벨 정리가 완료된 것은 아니다.** 이번 수치로 최종 모델을 확정하거나 H의 모든 오탐이 해결됐다고 주장하지 않는다. 자동으로 신뢰성 있게 결정할 수 없는 판매 단위는 보류했다.

## 평가와 해석

- 두 모델 모두 수정 검증 78장, 입력 640, 배치 16, NMS IoU 0.70을 사용한다.
- Precision/Recall/F1은 매칭 IoU 0.50의 전체 객체 합산(micro) 수치다.
- 신뢰도 50~90%를 5% 간격으로 비교한다. mAP는 별도로 신뢰도 0.001에서 계산한다.
- 원본 v2 결과도 함께 보존한다. **정답이 바뀌었으므로 이전 대비 수치 상승은 학습 성능 향상이 아니다.**
- 정답을 추가하면 못 찾은 객체(FN)도 늘어 Recall이 내려갈 수 있다.
- 이미 여러 번 확인한 검증 세트이며 예측 오류를 본 뒤 수정한 데이터다. 독립적인 최종 성능 증명에는 새로 수집하고 일관되게 라벨링한 평가 데이터가 필요하다.

## 재현 명령

```powershell
# 최초 한 번만: 기존 출력 폴더가 있으면 덮어쓰지 않고 중단한다.
.\.venv-train\Scripts\python.exe experiments/prepare_validation_revision.py

.\.venv-train\Scripts\python.exe experiments/evaluate_thresholds.py --model runs/detect/ozm_augmented/weights/best.pt --data dataset_corrected_v3_review/data.yaml --output runs/validation_revision_A
.\.venv-train\Scripts\python.exe experiments/evaluate_thresholds.py --model runs/detect/ozm_shear0/weights/best.pt --data dataset_corrected_v3_review/data.yaml --output runs/validation_revision_H
```

데이터와 `runs/`는 Git 제외 대상이다. 팀원은 원본 v2가 있어야 스크립트로 동일 수정본을 만들 수 있다.

## 재평가 결과 — 2026-09-08

신뢰도 65% 기준이다. mAP 두 열은 별도 신뢰도 0.001 평가 결과다.

| 정답 버전 / 모델 | Precision | Recall | F1 | mAP50 | mAP50-95 | TP / FP / FN |
|---|---:|---:|---:|---:|---:|---|
| 기존 v2 / A | 93.10% | 62.21% | 74.59% | 85.75% | 67.44% | 135 / 10 / 82 |
| 기존 v2 / H | 87.43% | 67.28% | 76.04% | 88.36% | 72.74% | 146 / 21 / 71 |
| 수정 검토본 / A | **94.48%** | 55.24% | 69.72% | 82.20% | 62.75% | 137 / 8 / 111 |
| 수정 검토본 / H | 90.42% | **60.89%** | **72.77%** | **86.87%** | **68.80%** | 151 / 16 / 97 |

A는 오탐이 10→8개, H는 21→16개로 줄었다. H에서 더 많이 줄었으므로 기존의 격차 일부에는 라벨 누락 영향이 있었다. 수정 후에도 H는 A보다 TP가 14개 많고 FP는 8개 많다. Precision은 A가 4.06%p 높고, Recall은 H가 5.65%p 높다.

정답이 31개 늘었지만 TP 증가는 A 2개, H 5개다. 나머지는 못 찾은 정답으로 남아 FN과 평가 난도가 늘었다. Recall과 mAP 감소를 모델 성능이 악화됐다고 해석하면 안 된다.
