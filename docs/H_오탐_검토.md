# H 모델 오탐 시각 검토

## 확인 범위와 기준

수정 valid 78장, 신뢰도 65%, NMS IoU 0.7, 정답 매칭 IoU 0.5로 A·H를 비교했다.
`predict()`로 별도 집계하지 않고 기존 평가와 동일한 `DetectionValidator` 경로에서 이미지별 박스와 TP 판정을 수집했다.
기존 수치 **A TP135/FP10/FN82, H TP146/FP21/FN71**와 정확히 일치하는지 코드에서 검사했다.

H의 오탐 21개가 있는 **16장 전부**를 직접 시각 검토했다.
그림은 왼쪽 정답, 가운데 A, 오른쪽 H 순이다. 정답은 초록색, 예측은 평가상 정탐이면 초록색·오탐이면 빨간색이다.
빨간색이 반드시 실제 오인식이라는 뜻은 아니다. 정답 누락도 포함한다.
각 예측의 `#번호`는 `records.json`의 해당 이미지 predictions 인덱스다.

아래는 21개 박스를 한 번씩 분류한 **검토자의 주된 원인 추정**이다. 확정된 데이터 오류 통계는 아니다.

## 이번 결과로 판단할 수 있는 다음 단계

1. **라벨 기준 정리가 먼저 필요한 이미지가 확인됐다.** 특히 `apple_092`, `apple_055`, `apple_027`, `pig_raw pork slices_044`는 실제 물체가 보이는데 대응 정답이 없다.
   수정하려면 잘린 물체·절단 상품·판매 단위를 일관되게 적용하고 A/H 모두 재평가한다. H만 유리하도록 선택적으로 정답을 추가하지 않는다.
2. **NMS 하나로 해결할 문제는 아니다.** 중복으로 분류한 것은 21개 중 1개다. 클래스 혼동·상품 단위 분할·누락 정답은 NMS를 조정해 직접 해결되지 않는다.
3. **임계값만 높여도 남는 오류가 있다.** 계란 포장 → 고기 96.7%, 껍질 → 양파 88.0% 사례가 있다.
4. 클래스 혼동에 대해서는 해당 포장·질감의 train 사례와 라벨 일관성을 확인해야 한다. 이 사진들만으로 학습률·batch·shear 중 원인을 확정하지 않는다.

현재 평가표의 A 우위는 유지하되, 그 표에 라벨 누락·단위 문제가 섞여 있다는 한계를 함께 기록한다.
이번 작업에서는 **라벨 수정, 재학습, 서비스 변경을 하지 않았다.**
