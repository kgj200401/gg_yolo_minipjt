# 기능명세서

## 1. 문서 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | AI 스마트 마트카트 |
| 목적 | 카메라로 상품을 인식하여 장바구니에 자동 추가하고, 구매 재료를 기반으로 요리와 조리법을 추천한다. |
| 주요 사용자 | 마트카트를 이용하는 고객, 프로젝트 시연자 |
| Backend | Python, FastAPI, SQLAlchemy, SQLite |
| Frontend | React, Vite |
| 객체 탐지 | Roboflow로 학습한 YOLO 모델 연결 예정 |

## 2. 서비스 범위

```text
카메라 영상 표시
→ 상품 탐지 또는 개발용 테스트 입력
→ 장바구니 자동 추가
→ 수량 및 총 구매금액 계산
→ 구매 완료
→ 레시피의 재료 종류와 수량 비교
→ 요리 추천 및 부족한 재료 표시
→ 요리 카드 선택
→ 재료 수량과 요리 방법 표시
```

현재 카메라 영상 표시는 구현됐지만 YOLO 탐지는 연결되지 않았다. 개발 단계에서는 접이식 테스트 입력에서 상품을 선택하여 탐지 결과를 대신한다.

## 5. 추천 레시피

| 요리 | 필요 재료 |
|---|---|
| 해물파전 | 대파 1대, 새우 8마리, 계란 1개 |
| 사과파이 | 사과 1개, 식빵 2장, 계란 1개 |
| 계란찜 | 계란 3개, 대파 반 대 |
| 제육볶음 | 고기 1팩, 양파 반 개, 대파 1대, 마늘 3쪽 |
| 새우볶음밥 | 새우 8마리, 계란 1개, 당근 반 개, 대파 반 대 |

소금, 설탕, 간장, 식용유 등 기본 조미료는 사용자가 보유한 것으로 가정한다.

## 6. 추천 계산 규칙

1. 상품별 장바구니 수량을 조회한다.
2. 레시피에 등록된 각 재료의 `amount`와 비교한다.
3. `장바구니 수량 >= 필요 수량`이면 해당 재료를 충족한 것으로 처리한다.
4. 일부만 보유하면 부족량을 `필요 수량 - 보유 수량`으로 계산한다.
5. 재료 일치율은 `수량을 충족한 재료 종류 / 전체 필요 재료 종류 × 100`으로 계산한다.
6. 모든 재료의 수량을 충족한 경우에만 `can_make=true`로 처리한다.
7. 추가 구매 목록은 부족한 재료 종류 수가 적은 순, 일치율이 높은 순으로 정렬한다.

예시:

```text
사과파이 필요: 사과 1, 식빵 2, 계란 1
장바구니: 사과 1, 식빵 1, 계란 1

충족 재료: 사과, 계란
부족 재료: 식빵 1장
일치율: 2 / 3 = 66.7%
제작 가능: 아니요
```

현재 장바구니 수량은 카메라가 인식한 상품 개수이다. 포장 중량이나 실제 낱개 구성은 측정하지 않는다.

## 8. 예외 처리

| 상황 | 처리 |
|---|---|
| 등록되지 않은 상품 추가 | HTTP 404와 오류 메시지 반환 |
| 없는 장바구니 상품 감소 | HTTP 404 반환 |
| 빈 장바구니 구매 | HTTP 400 반환 |
| 없는 레시피 조회 | HTTP 404 반환 |
| 요청 형식 오류 | FastAPI HTTP 422 반환 |
| 카메라 권한 거부 | 토스트로 권한 확인 안내 |
| FastAPI 연결 실패 | 서버 연결 실패 배지 표시 |

## 9. DB 구성

| 테이블 | 역할 |
|---|---|
| `products` | 상품명과 가격 저장 |
| `recipes` | 요리 이름 저장 |
| `recipe_ingredients` | 요리별 상품, 필요 수량, 단위, 표시 순서 저장 |
| `recipe_steps` | 요리별 단계 번호와 요리 방법 저장 |
| `cart_items` | 장바구니 상품과 수량 저장 |

인증과 사용자별 장바구니는 MVP 범위에서 제외한다. 따라서 현재 장바구니는 서버 전체에서 하나를 공유한다.
